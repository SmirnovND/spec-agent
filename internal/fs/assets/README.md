# Assets — ресурсы для spec-agent

## Структура

### `examples/` — примеры спецификаций
Готовые примеры спецификаций для разных типов компонентов:
- **controller_spec.md** — HTTP контроллер/обработчик запросов
- **usecase_spec.md** — бизнес-логика и сценарии использования
- **service_spec.md** — бизнес-сервисы и операции
- **repository_spec.md** — доступ к данным

Используйте эти примеры как:
- Шаблоны для создания новых спецификаций
- Справку по правильному оформлению (структура разделов, ссылки)
- Эталон качества спецификаций

### `go/prompts/` — промты Go-профиля
- `go/prompts/base/*.md` — базовые инструкции для стандартного `spec-agent init`
- `go/prompts/zenflow/*.md` — этапные инструкции для `--zenflow`

### `shared/prompts/` — общий слой для любых AI-систем
- `shared/prompts/entrypoint.md` — единая точка входа и порядок чтения инструкций
- `shared/prompts/core/*.md` — единое ядро правил и workflow, независимое от платформы
- `shared/prompts/modes/*.md` — workflow-режимы по типам задач:
  - `bugfix.md`
  - `development.md`
  - `refactor.md`
  - `tests.md`
  - `analysis.md`

Языковая политика:
- `shared/prompts/core/*` и `shared/prompts/modes/*` пишутся на английском.
- Спецификации рядом с кодом (`*.md`) и бизнес-описания пишутся на русском.

### `shared/prompt_specs/` — машинно-читабельный источник истины
- Каждый prompt хранится как `prompt.yaml` со структурой:
  - `persona`
  - `workflow_steps`
  - `must_rules`
  - `tool_policy`
  - `output_contract`
- Markdown в `shared/prompts/*` генерируется из этих YAML-файлов.

### `php/` — PHP-профиль
Ресурсы для PHP-проектов:
- `php/prompts/base/*.md` — базовые инструкции для `spec-agent init-php`
- `php/prompts/zenflow/*.md` — этапные инструкции для `init-php --zenflow`
- `php/examples/` — примеры PHP-спецификаций

### Конфигурация (`.spec_agent/config.yaml`)
Файл создается при инициализации и содержит:
- **roots** — список директорий, которые агент будет анализировать в первую очередь. Это помогает сузить контекст до папок с контроллерами, хендлерами или командами, где обычно лежат спецификации.
- **exclude** — опциональный список директорий/путей, которые нужно исключить из сканирования (например, технические подсистемы, не входящие в пользовательскую документацию HTML).

Используйте при:
- Интеграции AI-агента в ваш проект
- Установлении стандартов для спецификаций
- Понимании процесса планирования и реализации изменений

## Как использовать

### Настройка AI-агента
1. Используйте единый вход: `shared/prompts/entrypoint.md`
2. Entry-point сам применит `core/*.md` и выберет нужный режим из `modes/*.md`
3. Для Go: добавляйте `go/prompts/base/*.md`
4. Для PHP: добавляйте `php/prompts/base/*.md`
5. Для Zenflow-процессов используйте `*/prompts/zenflow/*.md` по этапам

### Генерация markdown из prompt.yaml
Для поддержки консистентности используйте генератор:

```bash
go run ./cmd/promptgen
```

Проверка, что markdown не устарел:

```bash
go run ./cmd/promptgen -check
```

### Архитектурное правило слоёв (обязательно)
- Сценарная бизнес-оркестрация (последовательность шагов, ветвления, принятие решений по сценарию) должна находиться в **usecase**.
- **Service** должен реализовывать отдельные шаги сценария и технические операции (доступ к репозиториям, преобразования, интеграции), которые вызывает usecase.
- Если логика описывает целый пользовательский/бизнес-сценарий, она не должна размещаться в service.

### Работа со спецификациями
1. Изучите `spec_rules.md` для понимания правил
2. Смотрите примеры в `examples/`
3. Следуйте структуре и семантике при создании новых спецификаций
