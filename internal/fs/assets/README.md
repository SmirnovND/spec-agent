# Assets — ресурсы для spec-agent

## Структура

### `examples/` — примеры спецификаций
Готовые примеры спецификаций для разных типов компонентов:
- **controller_spec.md** — HTTP контроллер/обработчик запросов
- **usecase_spec.md** — бизнес-логика и сценарии использования
- **service_spec.md** — бизнес-сервисы и операции
- **repository_spec.md** — доступ к данным

Используйте эти примеры как:
- Шаблоны для создания новых спецификаций
- Справку по правильному оформлению (структура разделов, ссылки)
- Эталон качества спецификаций

### `go/prompts/` — промты Go-профиля
- `go/prompts/base/*.md` — базовые инструкции для стандартного `spec-agent init`
- `go/prompts/zenflow/*.md` — этапные инструкции для `--zenflow`

### `php/` — PHP-профиль
Ресурсы для PHP-проектов:
- `php/prompts/base/*.md` — базовые инструкции для `spec-agent init-php`
- `php/prompts/zenflow/*.md` — этапные инструкции для `init-php --zenflow`
- `php/examples/` — примеры PHP-спецификаций

### Конфигурация (`.spec_agent/config.yaml`)
Файл создается при инициализации и содержит:
- **roots** — список директорий, которые агент будет анализировать в первую очередь. Это помогает сузить контекст до папок с контроллерами, хендлерами или командами, где обычно лежат спецификации.

Используйте при:
- Интеграции AI-агента в ваш проект
- Установлении стандартов для спецификаций
- Понимании процесса планирования и реализации изменений

## Как использовать

### Настройка AI-агента
1. Для Go: используйте `go/prompts/base/*.md`
2. Для PHP: используйте `php/prompts/base/*.md`
3. Для Zenflow-процессов используйте `*/prompts/zenflow/*.md` по этапам

### Работа со спецификациями
1. Изучите `spec_rules.md` для понимания правил
2. Смотрите примеры в `examples/`
3. Следуйте структуре и семантике при создании новых спецификаций

## Добавление новых ресурсов

Вы можете добавлять:
- Новые примеры для других типов компонентов (middleware, validator и т.д.)
- Промты для специфических задач (рефакторинг, оптимизация)
- Гайды и лучшие практики
